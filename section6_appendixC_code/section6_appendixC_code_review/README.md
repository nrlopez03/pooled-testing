# Paper-wide computation and code-review bundle

This bundle collects the code and data needed to audit every computational or enumeration-based
claim in the current manuscript. The components are intentionally kept separate:

- `current_exact/` contains the new, dependency-free exact experiment used for the main empirical
  claims in Section 6.
- `archived_pipeline/` contains a source snapshot of the earlier Gibbs, MILP, and PPO work discussed
  as exploratory material in Appendix C. It is historical research code and is not the source of
  the exact comparisons in Section 6.
- `paper_claims/` contains focused, dependency-free checks for numerical claims elsewhere in the
  paper: the strict three-agent adaptivity example and the boundary-sensitive high-health table.

## Start here: the current exact experiment

The main file is:

```text
current_exact/exact_small_instances.py
```

It implements, without sampling:

1. the optimal dynamic policy by posterior-state backward induction;
2. Exact-Joint Greedy;
3. Marginal-Product Greedy using exact posterior marginals;
4. the optimal static overlapping allocation;
5. the optimal static non-overlapping allocation; and
6. static non-overlapping greedy.

Run the paper experiment from the root of this bundle with:

```text
python3 current_exact/exact_small_instances.py \
  --output current_exact/reproduced_results
```

The implementation uses only the Python standard library and is intended for Python 3.10 or newer.
The fixed seed and default instance counts match Section 6:

- 300 instances with `(n,B,G)=(4,2,4)`;
- 200 instances with `(n,B,G)=(5,3,5)`; and
- 100 instances with `(n,B,G)=(6,3,3)`.

Reference outputs are in `current_exact/results/`:

- `exact_small_instances_raw.csv`: all 600 instance-level records;
- `exact_small_instances_summary.csv`: the three summary rows used in Section 6; and
- `archived_large_summary.csv`: aggregate numbers transcribed from the earlier large-instance
  pipeline and reproduced in Appendix C. This last file is not generated by the exact solver.

To compare a fresh summary with the reference while ignoring machine-dependent runtime fields, run:

```text
python3 current_exact/verify_against_reference.py \
  current_exact/results/exact_small_instances_summary.csv \
  current_exact/reproduced_results/exact_small_instances_summary.csv
```

To regenerate the LaTeX rows and narrative statistics reported in the paper from the reference
summary, run:

```text
python3 current_exact/render_reported_results.py
```

The two small CSV files in `archived_pipeline/small_archived_inputs/` can optionally be passed to
the exact solver using `--archived-n3` and `--archived-n5`. Those calculations are not used for the
current Section 6 table.

## Checks for claims outside Section 6

The paper's named three-agent example states that direct enumeration gives a particular optimal
static allocation and dynamic policy. Reproduce that complete enumeration certificate with:

```text
python3 paper_claims/verify_strict_adaptivity_example.py
```

The script checks the optimal allocations and dynamic branches, not just the displayed objective
values. It also reports the optimal static non-overlapping allocation.

Generate the boundary-sensitive high-health table directly from
`min{2, min_{1 <= s <= G} G/(s theta^(s-1))}` with:

```text
python3 paper_claims/generate_high_health_table.py
```

This audit found one manuscript rounding error: at `G=3` and `theta=.90`, the formula equals
`1.234567...` and therefore rounds to `1.23`, whereas the audited v12 source prints `1.24`. Pass
`--strict-manuscript` if a mismatch should produce a nonzero exit status.

## Archived Gibbs/MILP/PPO pipeline

The archived source was downloaded from:

```text
https://github.com/nrlopez03/pooled-testing
```

at commit:

```text
4d5de409cb10af9c9fdc8e8a62e5008f46e40af2
```

The primary files to inspect are:

- `archived_pipeline/source/greedyDynamicSample.py` — the earlier Gibbs-marginal dynamic heuristic;
- `archived_pipeline/source/milpSample.py` — the earlier static MILP comparison;
- `archived_pipeline/source/PPO_bucket_gymnasium_B2.py` through
  `PPO_bucket_gymnasium_B5.py` — sequential bucketed PPO training variants;
- `archived_pipeline/source/PPO_bucket_gymnasium_use.py` and
  `PPO_bucket_gymnasium_B5_use.py` — PPO evaluation scripts;
- `archived_pipeline/source/Pooled_Testing_Strategies.ipynb` — earlier small-instance strategy
  implementations; and
- `archived_pipeline/source/multGraphs.ipynb` and `singleGraphs.ipynb` — earlier analysis and
  plotting notebooks.

The `training/` directory and scheduler scripts are included so that the historical implementation
can be audited in context. Several files under `training/old_training/` are superseded experiments;
they are retained for completeness and should not be mistaken for the current Section 6 pipeline.

The two raw, 10,000-row output files underlying the table retained in Appendix C are included in:

```text
archived_pipeline/raw_reported_results/
```

Their reported means and standard errors can be regenerated and checked against
`current_exact/results/archived_large_summary.csv` using only the Python standard library:

```text
python3 archived_pipeline/reproduce_archived_table.py
```

The archived source has no pinned environment. Its imports indicate dependencies including NumPy,
pandas, SciPy, matplotlib, seaborn, scikit-learn, joblib, tqdm, PyTorch, TensorFlow, Gym/Gymnasium,
Stable-Baselines3, MOSEK, and Gurobi. MOSEK and Gurobi ordinarily require separate licenses. Many
archived scripts are configured by editing module-level constants and assume particular relative
data and model paths, so they should be treated as code to audit before being treated as turnkey
reproduction scripts.

Apart from the two raw files required for the retained Appendix C table, unrelated archived data,
model binaries, figures, log files, and Windows `Zone.Identifier` metadata are deliberately
excluded. They are not needed for claims that remain in the manuscript.

There is one important limitation. The archived PPO evaluation programs refer to Stable-Baselines3
checkpoint files in directories such as `PPO_4Bucket_G*` and `PPO_5Bucket_G*`, but those `.zip`
checkpoints are absent from the archived GitHub repository. The repository also lacks a pinned
software environment. Consequently, the retained Appendix C numbers can be audited exactly from
the included raw outputs, and the historical algorithms can be inspected, but the PPO rows cannot
currently be regenerated end to end from the original trained policies. Nick would need to supply
the missing checkpoints and environment metadata, or the policies would need to be retrained.

## Verification already performed

On 2026-09-15, the exact experiment was rerun from the bundled source with its default arguments.
All non-runtime fields in `exact_small_instances_summary.csv` reproduced exactly. The observed
headline values were:

```text
random_n4_b2_g4: max adaptivity gap 1.074385; min Exact-Joint/OPTdyn 0.834312
random_n5_b3_g5: max adaptivity gap 1.050053; min Exact-Joint/OPTdyn 0.897691
random_n6_b3_g3: max adaptivity gap 1.050708; min Exact-Joint/OPTdyn 0.896154
```

The focused verifier also reproduced the strict example's static value `0.24658099248`, dynamic
value `0.284557136`, and gap `1.154010830835`. The two archived raw files reproduced every mean and
standard error in the Appendix C table. All 40 Python files, 11 shell scripts, and 3 notebooks in
the archived commit are present in this bundle, and the Python sources passed bytecode compilation.

The archived pipeline was not executed end to end because its historical environment, solver
licenses, and required PPO checkpoints are unavailable. The remaining results in the paper are
analytic proofs or citation-based complexity statements and do not require numerical reproduction
code.

## Suggested audit checklist

For the exact Section 6 experiment:

1. Check the health-profile bit convention and product-prior world weights.
2. Check the posterior-state representation `(support, cleared, remaining_budget)`.
3. Check the negative/positive support split and the immediate welfare on the negative branch.
4. Check that optimal dynamic, Exact-Joint Greedy, and Marginal-Product Greedy are evaluated under
   the true posterior distribution.
5. Check the inclusion-exclusion calculation for overlapping static allocations.
6. Check the dynamic programs for optimal and greedy non-overlapping static allocations.
7. Check tie breaking, random-instance generation, summary statistics, and the head-to-head rates.

For Appendix C's archived pipeline:

1. Distinguish Gibbs estimation error from the product-of-marginals scoring approximation.
2. Check Gibbs feasibility updates after positive tests and the handling of cleared agents.
3. Check whether compared methods use the same population and the same realized health profile.
4. Check the MILP objective and whether its pools are overlapping or non-overlapping.
5. Check PPO state compression, sequential pool construction, reward definition, and model loading.
6. Record all random seeds, training budgets, bucket counts, solver versions, and data/model paths
   needed for a genuine rerun.

For the paper-wide focused checks:

1. Confirm that the strict-example verifier certifies the allocations and policy branches as well
   as the objective values.
2. Correct the `G=3`, `theta=.90` high-health table entry from `1.24` to `1.23` before release.
3. Distinguish reproduction of Appendix C's aggregation from an end-to-end rerun of PPO training
   and evaluation.
