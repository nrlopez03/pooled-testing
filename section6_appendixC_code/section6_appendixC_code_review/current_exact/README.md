# Exact small-instance solver

`exact_small_instances.py` is a dependency-free implementation of:

- optimal dynamic testing by memoized posterior-state backward induction;
- Exact-Joint Greedy, evaluated under the exact joint posterior;
- Marginal-Product Greedy, evaluated under the exact joint posterior; and
- optimal static overlapping and non-overlapping testing; and
- static non-overlapping greedy, which repeatedly selects the best prior-value pool among agents
  not used by an earlier selected pool.

The dynamic-programming state is `(posterior support, cleared agents, remaining budget)`. The solver
stores the optimal next pool at every state and therefore constructs an explicit optimal policy tree.

The paper uses this code both as an auditing tool and for its reproducible small-instance
comparison. From the root of the review bundle, the reported experiment is generated by:

```text
python3 current_exact/exact_small_instances.py \
  --output current_exact/reproduced_results
```

The script can also reproduce the archived small-instance calculations from the earlier revision:

```text
python3 current_exact/exact_small_instances.py \
  --archived-n3 archived_pipeline/small_archived_inputs/data_N3_d2_B2_G3.csv \
  --archived-n5 archived_pipeline/small_archived_inputs/data_N5_d2_B3_G5.csv \
  --output current_exact/reproduced_results
```

The two archived CSV files are in the public `pooled-testing` repository under `data/`.  Those
outputs are not used as evidence in the theory-first manuscript.

`results/archived_large_summary.csv` records the aggregate means and standard errors reproduced in
Appendix C from the earlier large-instance Gibbs/PPO pipeline.  The archived Gibbs and static
evaluations did not use a common realized health vector within each population row, so the file
marks paired comparisons as invalid.  Only the aggregate means are retained in the paper.

To render and verify the manuscript's Section 6 and greedy head-to-head table rows from the summary
CSV, run:

```text
python3 current_exact/render_reported_results.py
```

The program is intended for roughly `N <= 7`. It enumerates all `2^N` health profiles and all
feasible pools, so it is a validation tool rather than a population-scale optimizer.
